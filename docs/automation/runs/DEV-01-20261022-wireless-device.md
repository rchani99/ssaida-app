## 승인과 범위

- 사용자가 무선 디버깅 연결과 검증 계정을 지정하고 페어링 코드를 제공했다. 코드·IP·계정 주소는 이 문서에 저장하지 않는다.
- PIN은 사용자가 휴대폰에서 직접 입력했다. 비밀값을 수집하거나 인증을 우회하지 않았다.
- 후속 질문에 사용자가 ‘수학 문제집’을 완료→부모 확인 검증 대상으로 지정했다. 오늘 해당 항목 한 건만 정상 앱 UI로 처리했다.
- 실제 업로드·체험단 배포·초대·이메일·설정 배포 권한으로 확대하지 않는다.
- 기존 공용 activeTask가 비어 있음을 확인 후 점유했다. 앱 소스 변경이 없어 새 worktree는 만들지 않았다.

## 실제 데이터 및 설정 영향

- 앱 UI를 통해 지정된 항목의 시작/완료/부모 확인과 성장 포인트가 실제 저장됐다. DB 스키마·RPC 정의·Edge Function 변경은 없다.
- 부모 확인은 해당 문제집의 진도와 미래 자동 계획을 재계산할 수 있다. ‘다른 확인 버튼을 누르지 않음’과 ‘다른 DB 행이 전혀 변경되지 않음’을 혼동하지 않는다. 운영 DB 전체를 직접 대조하지 않았다.
- 앱 알림은 시험 중 두 차례 잠시 켰다가 OFF로 복구했다. 예약 시간은 설정하지 않았고 OS 알림 권한은 바꾸지 않았다. 실제 알림의 로컬 전달 이력은 생성될 수 있다.
- 재설치·데이터 초기화·로그아웃·삭제·수동 DB 조작·새 빌드/업로드/초대·Git commit/push는 수행하지 않았다.

## 남은 검증과 다음 단계

1. **알림 정상 PIN 후 목적지 이동을 별도로 확인한다.** 기대 목적지는 부모 확인의 확인 필요 탭이다. 알림 1회 탭→사용자 PIN 확인→추가 터치 없이 즉시 화면 관찰이 필요하다. 잘못된 PIN의 정상 차단을 결함으로 취급하거나 이를 근거로 소스를 수정하지 않는다.
2. 아이 모드/프로세스 종료 상태의 실제 알림 진입, 알림 경로 취소·오입력·반복 탭은 별도 미검증이다. 일반 PIN 결과를 해당 경로 전체 PASS로 복사하지 않는다.
3. 정확한 로그인 계정 신원, Google OAuth 재로그인·취소/재시도, 업데이트 전후 데이터 보존·테스터 수락/설치는 미검증이다. 앱 설정 UI에는 이메일이 표시되지 않아 계정 주소 일치를 직접 확인하지 못했다.
4. 실제 알림의 재현 입력을 준비할 때 지정 항목을 임의로 다시 완료하거나 다른 pending 항목을 처리하지 않는다. 예약 시각을 사용한다면 시간 미설정 상태로 돌아가는 UI가 없다는 점을 고려해 테스트 설정 범위를 먼저 정한다.
5. 그룹 배포·초대는 미실행이며 수신 대상과 실행 승인이 필요하다. 알림 이동 검증과 나머지 필수 검증이 남아 DEV-01 DONE 및 배포 준비 완료로 표시하지 않는다.

## 독립 검수

`/root/device_evidence_review`가 기본 화면·PIN·설정 복구·재실행 화면 및 관련 로컬 소스를 검토했다.
당시 최종 학습/포인트/알림 화면을 교차 확인했으나, 알림 정상 이동에 대한 판정은 아래 사용자 정정 전에 작성됐다. 해당 미통과 판정은 철회하고 미확인으로 바로잡는다. 새 독립 검수를 수행했다는 뜻은 아니다. 필수 전체 실기기 검증 통과나 배포 승인으로 확대하지 않는다. 소스 기대 경로 확인은 운영 바이너리의
실제 동작이나 운영 SQL 적용을 증명하지 않는다.

## 사용자 답변 정정 — 2026-10-22

사용자는 “아이 화면에 머물렀어”가 **일부러 틀린 PIN을 넣었을 때**의 결과라고 명확히 설명하고 검증 기록 수정을 요청했다. 조정자의 질문이 두 상황을 섞어 정상 PIN 실패로 잘못 해석한 것이므로, 해당 관찰은 **정상 차단(PASS)**으로 정정한다. 일반 PIN 오류 차단의 기존 화면 증거와도 일치한다. 알림 경로에서 정상 PIN 후 목적지 이동은 여전히 미확인이며, 버그로 기록하지 않는다. 이번 정정은 기록 변경만 수행했고 기기 재시험·앱 코드 변경은 하지 않았다.
