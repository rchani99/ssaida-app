# Ssaida 제품 결정

기준일: 2026-10-22. 제품 철학은 **“오늘이 모여 습관이 됩니다.”** 초등학생의 자기주도
학습 습관 형성과 부모의 학습 관리 부담 감소를 목표로 한다.

## 기준과 근거

- U1: 이 채팅의 2026-10-22 최종 「쌓이다(Ssaida) 자율 개발 에이전트 운영 체계 구축」 요청.
- U2: 같은 요청의 후속 답변 「Ssaida(쌓이다) 자율 개발 에이전트 — 목표 및 운영 지침」 및 DEV-01~27 목록.
- U3: 2026-10-22 DEV-01 착수 요청. 기존 Firebase 상태 확인과 남은 검증·준비를 승인하며 실제 배포·초대는 준비 후 별도 승인.
- U4: 2026-10-22 DEV-02 착수 요청. 기존 구현 확인, 필요한 개선 분담, 개발부터 독립 검수까지 승인. 실제 배포는 준비 후 별도 승인. DEV-01의 완료 판정을 변경하는 지시는 아님.
- 우선순위: 최신 명시적 사용자 정책 → 이 문서 → 실제 소스코드/DB 구현 상태 → 개발 백로그 → 과거 ChatGPT 대화.
  코드는 현재 동작의 근거이며 목표 정책을 자동으로 바꾸지 않는다. 충돌은 양쪽을 기록하고 보고한다.
- 참조 대화 「계정 관리 방법 안내」의 전체 답변 본문은 접근하지 못했다. 이 문서는 U1/U2의 직접 제공 내용을 근거로 한다.
- 결정 상태와 구현 상태는 별개다. 코드·문서 정적 확인을 운영 DB 직접 확인이나 실기기 통과로 표현하지 않는다.
  관련 증거와 기존 브랜치는 [현황](project-status.md), 실행 조건은 [백로그](development-backlog.md)에 정리한다.

## 2026-10-25 문제집 폼 변경 승인

사용자가 문제집 등록·수정 버튼 정리와 저장·취소 후 폼 닫기를 직접 승인했다. 등록은 ‘등록’, 수정은 ‘저장’으로 표시하고 옆에 ‘취소’를 둔다. 상단 ‘등록 닫기’를 제거하고 성공/취소 후 목록으로 돌아간다. 실패 입력 보존과 저장 중 중복 제출 방지를 검증한다. 구현 상태는 [DEV-11-FORM 기록](automation/runs/DEV-11-20261025-workbook-form.md)을 따른다.
이는 관리 UI 세부 범위이며 오늘 적용·계획/휴식일/통계 정책·신규 알림 변경을 승인하지 않는다. 실제 배포는 검증 결과 보고 후 별도 승인이다.

## 상태와 변경 관리

이번 작업의 표준 상태는 U1의 `TODO / IN_PROGRESS / BLOCKED / REVIEW / DONE`이다.
U2의 미착수·분석 중·구현 중·검증 중·완료·차단은 보고용 세부 단계로 매핑한다.
이는 같은 요청의 두 상태 표현을 구분한 문서 운영 방식이며 제품 정책 변경은 아니다.

정책 변경 시 결정 내용·상태·근거·영향 과제·현재 구현과의 차이를 함께 갱신한다.
과거 운영 배포 기록과 기존 브랜치 보고서는 삭제하지 않는다. 목표 정책이 확정되어도
실제 코드·운영이 전환되기 전에는 사용자 안내를 완료된 기능으로 바꾸지 않는다.

## PD-13 — 완료·확인 대기·부분 완료 표시 (2026-10-26)

- 결정 상태: 사용자 직접 확정. 부모 확인 후 `PARENT_CONFIRMED`만 ‘완료’로 표시하고 완료 수·완료율에 포함한다.
- `CHILD_COMPLETED`는 ‘확인 대기’, `PARTIAL`은 ‘부분 완료’로 별도 표시·집계한다. 시작 전·진행 중·다시 하기는 확인 대기로 바꾸지 않는다.
- 포인트 지급 규칙, 저장·상태 전이·DB/API 계약은 유지한다. 날짜가 지나도 확인 대기를 자동으로 미완료로 전환하지 않는다.
- 관련 과제: DEV-10-STATUS. 기존 화면·통계 의미의 일관성 개선이며 DEV-10 전체/P2 통계 신규 기능 착수 승인은 아니다.
- 구현 상태: REVIEW. 소스 1d85ca6 구현·관련 로컬 검증·독립 검수 통과. 실기기 검증은 일괄 진행 예정이며 배포된 APK에는 아직 반영되지 않았다.
- 근거: 개발 채팅에서 2026-10-26 사용자가 위 표시 정책과 에이전트 구현·검수를 직접 승인했다. 실기기 검증은 다른 변경과 모아서 진행하고 배포는 계속 보류한다.
- 이전 ‘통계의 아이 수행/부모 확인 의미 미결정’은 접수 당시 이력이며 이 결정으로 해소한다.

## PD-14 — 정기 공부 이어가기·밀린 공부 (2026-10-26)

- 결정 상태: 사용자 최종 정책 확정. 과거 미완료 분량을 다음 정기일에 반영하고 임의로 하루 분량을 두 배로 늘리지 않는다. 부분 완료 후에는 실제 완료 진도 이후부터 생성한다. 비정기일에는 정기 공부를 자동 생성하지 않으며 부모가 오늘에 추가/이번에는 넘기기를 선택할 수 있다. 무선택도 다음 정기일 생성을 막지 않는다.
- 지난 이력 보존, 동일 페이지 활성 배정 중복 방지, 원본과 재배정 관계 명확화, 일회성 기존 규칙 유지. 넘기기는 완료가 아니며 진도를 올리지 않는다.
- 밀린 공부는 지난 날짜의 처리 가능한 정기·일회성 공부만 표시. 오늘 공부와 부모 확인 대기는 제외한다. 이미 오늘 반영된 분량을 다시 추가하지 않는다. 이전 ‘오늘 공부도 미완료 목록 표시’ 요구는 폐기한다.
- UX는 사용자 제공 상단/최초 안내/빈 화면 문구와 (?) 다시 보기, 아이 화면의 단순한 오늘 목록을 따른다.
- 관련 과제: DEV-13-CARRYOVER. 구현 상태: UI 선행 구현·로컬 검증·독립 검수 PASS, DB/RPC 재배정 구현 전 정책 충돌 확인 대기(BLOCKED). 운영 적용 없음.
- 기존 구현과 충돌하여 확인 대기: 부모 확인 대기 임시 진도 유지 여부, 원래 문제집 ID 없는 과거 수동 추가의 연결 방식, 선생성 미래 배정을 오늘로 옮길 기준. 사용자 질문 답변 전 해당 규칙을 새로 결정하지 않는다.
- 운영 DB 변경이 필요한 경우 영향도·검증 결과를 먼저 보고하고 사전 승인 후 적용. 현재 배포 보류 유지.
