## 운영 DB 영향 사전 보고

UI 필터만 넓히면 중복 재배정·통계 중복·진도 불일치가 발생하므로 DB/RPC 변경이 필요하다. 정기 이력의 활성 배정 연결/정리 상태를 보존하는 최소 메타데이터와 자녀 단위 잠금·중복 요청 처리가 후보이다. 기존 이력 일괄 재생성·삭제·완료 처리 또는 이름 기반 자동 연결은 하지 않는다. 신규 메타데이터 기본값과 기존 데이터 호환, RLS/함수 권한, 생성·시작·완료·부모 확인·분량 변경의 오래된 요청 보호를 함께 검증해야 한다. 구체 migration은 정책 경계 확인 후 확정하며 운영 적용은 별도 영향도·검증 결과 보고 후 승인 대상이다.

## 현재 검증 환경

Docker CLI는 있으나 로컬 Docker 엔진이 실행되지 않아 PostgreSQL 컨테이너 조회가 실패했다. 운영 DB를 대신 사용하지 않는다. 실제 SQL·동시 요청 회귀가 완료되지 않은 상태를 로컬 UI 테스트로 대체하지 않는다.

## 필수 검증 계획

1. 미시작 → 다음 정기일 같은 진도/일일 분량, 원본 보존.
2. 부분 확인 → 실제 확인 진도 다음 쪽, 중복 없음.
3. 비정기일 오늘 추가 → 정기일 생성과 같은 활성 배정 보호.
4. 넘기기 → 재배정 요청만 정리, 실제 진도 불변.
5. 무선택 → 다음 정기일 정상 생성.
6. 오늘 추가 후 다시 미완료 → 재배정 관계 유지, 누적 카드/분량 없음.
7. 여러 날짜 미완료 → 처리 가능한 대표 항목만, 원본 이력 보존.
8. 다음 정기일 계획 선생성 → 기존 활성 배정과 충돌 판별, 중복 추가 방지.
9. 수동 변경 분량 → 보호·충돌 안내, 임의 분량 덮어쓰기 금지.
10. 생성/API 중복 및 동시 요청 → 잠금/멱등성 검증.
11. 확인 대기 → 확인 필요에만 표시, 미완료 제외.
12. 기간을 가로지르는 이월 → 완료율 분모/분자 중복 방지, 이력 조회 보존.

실기기 검증은 다른 변경과 일괄 진행하고 배포는 보류한다. 독립 검수 전 구현 완료나 테스트 성공으로 기록하지 않는다.
