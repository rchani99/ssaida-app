# 자율 개발·검수 설정 점검 결과

> 아래는 최종 제품 백로그 수립 **이전** 설정 점검 이력이다. 이후 정책·승인 범위는
> [제품 결정](../product-decisions.md)과 [백로그](../development-backlog.md)가 우선한다.
> 이 문서의 DEV-01은 LEGACY-AUTO-01이며 신규 Firebase 과제가 아니다. 당시 “다음 실행”은 현재 착수 지시가 아니다.

사용자 요청: 실제 에이전트 설정을 확인하고 반복 지시 없이 개발부터 검수까지 진행하도록 보완.

## 확인한 기존 설정

- 예약 ID `100-2`, 이름 `쌓이다 자율 개발·마케팅·검수 — 체험과 출시`, 로컬 heartbeat, ACTIVE.
- 실행 시간: 한국시간 매일 09·12·15·18·21시.
- 대상 채팅: `쌓이다 오늘 하루 할일` (`01a12eee-6360-7fe1-aa67-3f816397f27d`).
- 역할은 기존 예약 프롬프트에 지정되어 있었으며 프로젝트 `.codex`에는 별도 역할 설정 파일이 없었다. 조정자가 매 실행 구현·검수 담당을 생성하는 운영 방식이다.
- 개발·테스트·독립 검수 권한은 이미 있었지만, 프로젝트 AGENTS.md에는 Expo 문서 확인 지시만 있었고 공용 개발 큐와 구체적인 재개·완료 절차가 없었다.

## 반영한 변경

- AGENTS.md에서 자율 실행 지침과 상태 파일을 읽도록 연결했다.
- `development-workflow.md`에 개발 우선 선택, 격리 작업, 구현과 별도 검수 담당 위임, 변경별 검증, 재수정과 재검수, 결과 저장과 후속 작업 기준을 정의했다.
- `state.json`에 DEV-01 준비 상태를 만들었다. 과거 마케팅 결과를 새 개발 완료로 이관하지 않았다.
- 기존 마케팅 운영 문서에는 새 실행 기준 링크만 추가하고 기존 목표·기록을 유지했다.
- 기존 예약 프롬프트 앞부분에 새 절차 우선 적용을 추가했다. 기존 ID·이름·유형·일정·대상 채팅·상태·생성 시각과 기타 기존 필드는 보존했다. 예약을 중복 생성하지 않았다.

## 검증과 독립 검수

- 예약 업데이트 도구가 `100-2`, `ACTIVE`를 반환했다.
- 실제 저장된 TOML을 다시 파싱해 새 프롬프트와의 완전 일치 및 기존 필드 보존을 확인했다.
- 상태 JSON 파싱, 원본 문서 참조 경로, 초기 activeTask/lastRun 값, 변경 diff 공백 검사를 확인했다.
- 독립 검수 담당 `workflow_review`가 공용 activeTask 소유권 충돌 가능성 1건을 지적했다. 기존 예약 채팅 단일 조정자, 타인 점유 시 읽기 후 종료, 저장·해제 전 작업 ID와 소유자 일치 확인, 중단 확인 후 인계 규칙을 추가했다.
- 같은 검수 담당이 수정된 문서와 실제 예약 프롬프트를 재검수해 승인했다. 추가 필수 수정 없음. 수정 1회.
- 앱 소스 변경이 없는 설정 작업이므로 앱 테스트·빌드·실기기 검증은 수행하지 않았다. 설정 검수와 앱 개발 검수를 구분한다.

## 다음 실행

다음 예약은 DEV-01에서 구체적인 결함 또는 검증 공백과 완료 조건을 정하고 구현·검증·독립 검수를 진행한다. 첫 실제 예약 개발 실행의 성공은 아직 미확인이다. 점검 중 대상 채팅은 플러그인 연결 작업의 승인 대기로 표시됐으며, 그 승인을 이 작업에서 대신 처리하거나 권한을 우회하지 않았다.
