## 사용자 승인에 따른 테스트 계정 초기화

첫 계정은 보존하기로 결정했다. 사용자가 별도로 지정한 두 번째 계정 역시 기가입 상태여서,
해당 계정 데이터 전체를 삭제하고 새로 가입하도록 명시 요청했다. 기존 14일 대기 정책은
변경하지 않고, 해당 한 계정만 기존 관리자 Auth hard-delete API로 처리했다.

실행 전 정확한 이메일·UUID·Google identity를 대조하고 운영 FK cascade와 Auth 삭제 후
영수증 익명화 트리거의 연결·활성 상태를 읽기 확인했다. 자녀 1명, 공부 항목 2개,
계획 2개, 과제 4개, 컬렉션 1개, 성장 이벤트 2개, 파일럿 기록 2개, PIN 1개,
삭제/PIN 요청 기록 3개, 영수증 3개, Storage 소유 파일 0개를 확인했다.
독립 검수 후 11:16 KST 관리자 삭제 성공과 Auth 재조회 404를 확인했다.

삭제 후 사전 저장된 ID를 기준으로 계정·프로필·자녀·PIN·학습·컬렉션·성장·파일럿·요청 기록
잔존 0건을 확인했다. 영수증 3개는 DELETED 및 계정/요청 ID null로 보존됐다.
원래 보존 계정은 계정 1·프로필 1·자녀 1·과제 5건으로 전후 동일했다.
이는 해당 건수 비교이며 다른 계정 전체 내용의 불변 검증이나 인프라 백업·로그 소거가 아니다.
Google 계정 자체, 공용 카탈로그, DB 스키마·정책·함수는 변경하지 않았다.

관리자 삭제 후 앱을 열면 기존 로컬 세션으로 이름 입력 단계가 표시됐지만,
서버의 해당 이메일 계정은 0건이었다. 이를 신규 가입 성공으로 판정하지 않았다.
프로필 부재를 초기 설정으로 처리하는 분기와 관련된 것으로 추정하며, 정규 영수증 기반
삭제 흐름과는 별도 관찰이다. 사용자가 앱 저장공간 초기화를 명시 승인한 뒤
`pm clear com.ssaida.app` 성공과 정상 로그인 화면을 확인했다.
이 기기의 로그인·캐시·계정별 알림 설정도 초기화됐으며 원래 계정의 서버 데이터는 유지된다.

## 증거와 다음 단계

개인정보·인증 비밀값을 공개 저장소에 올리지 않는다. 화면·개인 식별 ID·운영 실행 도구는
Git 제외 `outputs/device-verification-20261023/`에 보관한다. 키는 메모리에서만 사용했으며
결과에 기록하지 않았다. 관련 없는 최근 앱 목록의 임시 캡처는 제거했다.

아래 후속 기록에서 새 OAuth·온보딩·통신 복구·알림 정상 PIN 목적지 결과를 구분한다.
체험단 개별 설치는 아직 완료 판정하지 않는다. 새 빌드·배포·초대·실메일 발송은 수행하지 않았다.
이번 관측 범위와 제품 과제 전체 완료를 구분하며 DEV-01/02는 REVIEW를 유지한다.
다음 재개 시 작업 소유권과 실제 앱 화면을 다시 확인하고, 완료한 계정 삭제·앱 초기화를 반복하지 않는다.

## 후속 재가입과 초기 설정 입력 검증

사용자 Google 인증 완료 응답 후 운영 읽기 조회에서 지정 테스트 이메일의 Auth 계정 1건,
이전 삭제 UUID 부재, onboarding_completed=false, 자녀 0건을 확인했다.
앱의 이름 입력 1/3 단계와 함께 확인했으므로 이전 삭제 세션의 화면과 구분된다.

- 빈 이름: `아이 이름을 입력해 주세요.` 오류와 1/3 유지 확인 (`name-current2.xml`).
- 목표 미선택: `하루 목표 공부시간을 선택해 주세요.` 오류와 2/3 유지 확인 (`target-required.xml`).
- PIN 미입력: `부모 PIN은 숫자 4자리로 입력해 주세요.` 오류와 3/3 유지 확인 (`pin-required.xml`).
- 테스트 이름 `Test`, 목표 30분으로 준비했다. 현재 온보딩에 학년 입력란은 없다.
- 키보드가 버튼을 가린 상태의 임시 문자 입력은 제거했다. 일시적인 ADB 연결 단절로 가져오지 못한
  `name-required.xml`은 근거로 사용하지 않는다. 성공적으로 재조회한 새 증거만 판정했다.
- 별도 담당이 새 계정 읽기 결과와 위 3개 UI 증거를 독립 검수해 범위 한정 PASS로 확인했다.

PIN 입력 전 조회는 완료 프로필 0·자녀 0·PIN 자격 기록 0건이었다. PIN 값이나 해시는 읽지 않았다.
이 입력 전 체크포인트 이후의 저장 결과는 다음 절에 기록한다.

사용자가 별도 총괄 채팅에서 확정한 역할 인계 문서를 읽고 공용 상태의 개발 예약 ID를
`automation-2`, 개발 단일 조정자를 이 개발 채팅으로 갱신했다. 진행 중인 검증과 승인 범위는 유지했고
예약 도구 변경·다른 채팅 답장은 수행하지 않았다.

## 온보딩 저장 및 실제 통신 실패 복구

- 사용자가 새 PIN 입력과 완료를 직접 수행한 후, 읽기 조회에서 Auth 1·완료 프로필 1·자녀 1·
  PIN 자격 기록 1건을 확인했다. 자녀는 Test, 목표는 30분이다 (`onboarding-saved.json`).
- 테마 선택 화면에서 공룡을 선택하고 Test·목표 30분·학습 0건·공룡 0/24포인트의 아이 홈을
  확인했다 (`theme-selected.xml`, `fresh-child-home.xml`). 이후 일반 정상 PIN으로 부모 대시보드
  진입도 확인했다 (`new-parent-home.xml`). 단일 행수 관측은 동시 제출·중복 저장 경합 검증이 아니다.
- 기기의 임시 루프백 프록시로 실제 통신을 차단하고 앱을 다시 열었을 때 프로필 조회 오류와
  `다시 시도`가 표시됐다. 초기 설정 화면으로 잘못 이동하지 않았다 (`network-failure.xml`).
- 프록시 키 삭제만으로 Android의 유효 프록시가 해제되지 않아 첫 재시도는 실패했다
  (`network-retry-settled.xml`). 명시적인 프록시 해제 후 앱을 재시작하지 않고 다시 시도하여
  동일 Test·30분·공룡 홈 복귀를 확인했다 (`network-retry-explicit-reset.xml`).
- 프록시 관련 5개 설정을 모두 원래의 미설정(null)으로 복구했다 (`network-final.json`).
  `network-retry-success.xml`은 파일명과 달리 로딩 화면이므로 성공 근거로 사용하지 않는다.
- 별도 담당의 위 증거 읽기 검수 PASS. 원격/기기 재실행 검수와 구분한다.

## 실제 알림 및 종료 상태 진입

새 테스트 계정의 앱 알림은 OFF, Android 알림 권한은 차단 상태였다. 검증을 위해 일시적으로
권한 및 전체 알림을 켜고 부모 확인시간 알림을 11:50에 저장했다. 미완료 알림은 OFF 유지했다.
아이 화면으로 전환 후 HOME과 `am kill`을 사용했고, 11:48:21 프로세스 부재를 확인했다.
이는 강제 중지(force-stop)와 다르다. Android 알람의 요청 시각 11:50 및 약 2분 2초의
전달 구간을 관측했고, 11:52:21 실제 제목·본문과 새 프로세스를 확인했다
(`actual-notification-arrival.json`). 새 프로세스는 알림 탭 전 수신 시점에 이미 존재했다.
해당 실제 알림을 누르자 부모 PIN 인증 화면이 표시됐다 (`cold-notification-pin.xml`).
사용자가 정상 PIN을 직접 입력한 후 추가 탐색 없이 `부모 확인`, `확인 필요`,
`지금 확인할 공부가 없어요.`가 표시된 목적지를 확인했다 (`cold-notification-destination.xml`).
이로써 프로세스 종료 상태의 실제 예약 알림 수신→PIN 요구→정상 인증→부모 확인 목적지의
범위는 PASS다. 11:52:21은 수신을 관측한 시각이며 정확한 OS 전달 시각으로 단정하지 않는다.
다른 앱의 알림 내용은 저장하지 않았다.
뒤로 가기에서 앱이 종료돼 다시 열자 아이 모드였으므로, 설정 복구용 정상 PIN 입력을 사용자에게
요청했다. 사용자 입력 후 다음 복구를 완료했다.

## 설정 복구와 최종 검수 범위

- 부모 확인시간 알림 OFF를 저장하고 전체 알림도 OFF로 복구했다. 미완료 알림은 계속 OFF다
  (`reminders-disabled.xml`, `notification-app-restored.xml`).
- Android의 쌓이다 알림 권한을 원래 차단 상태로 복구했다 (`notification-os-restored.xml`).
  11:59:12 시스템 조회에서 쌓이다 예약 알람 0건·표시 알림 레코드 0건을 확인했다
  (`notification-cleanup-counts.json`). 앱으로 돌아오면 새 테스트 계정의 아이 홈이 표시된다.
- 시각을 공란으로 초기화하는 UI가 없어 테스트 계정에 **비활성 11:50** 값은 남는다.
  예약과 알림은 꺼져 있다. 다른 계정의 알림 값을 편집하지 않았다.
- 앱 코드·DB 스키마·API·배포 설정 변경은 없다. 이번 일련의 실행에서 사용자 승인된
  한 테스트 계정 삭제 및 새 계정의 정상 온보딩 데이터 생성만 수행했다. 배포·초대는 하지 않았다.
- 이번에 별도 수행하지 않은 항목: APK5 알림의 잘못된 PIN·취소 및 부모 모드에서 재인증,
  온보딩 동시 제출 경합, Family Link 대상 기기 사례, 개별 체험단 수신·설치 결과.
  이전 APK의 결과를 이번 APK의 직접 관측 결과로 옮기지 않는다.
- 별도 담당이 온보딩·통신 복구·실제 알림/PIN 목적지 증거를 읽어 PASS로 판정했다.
  문서 변경은 공백/링크/범위·민감정보 검토로 확인하며 기능 코드 회귀를 불필요하게 재실행하지 않는다.

검증 기록의 Git 반영은 `c881e36` 기반 격리 작업 디렉터리에서 이 보고서와 백로그만 대상으로 한다.
원시 기기 증거·관리자 실행 도구·로컬 상태 파일·다른 작업 변경은 공개하지 않는다.
새 APK가 없으므로 기존 배포 태그를 옮기거나 새 배포 태그를 만들지 않는다.
